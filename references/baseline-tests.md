# 基线与回归场景

## 无 Skill 基线暴露的问题

1. 时间压力下会直接做到最终成片，只做内部低清检查，不等待用户确认。
2. 会凭经验规定固定场景秒数、镜头数量或“中央安全区”，而不是从 SRT、平台 UI 和项目参考图得出。
3. 会把逻辑画布直接设为 2160×3840，忽略 HyperFrames 高 DPR、临时空间和内存风险。
4. 会提出截图局部放大，却没有先保证完整 `contain` 和移动端可读。
5. 没有把“缺少月明宇航员参考图”视为 AI 品牌图生成的阻断条件。

## 带 Skill 应满足

- 急单也先交可快速确认的真实时间线预览，不把内部检查冒充用户签字。
- 倍速只改一个配置，所有依赖时间同步重建。
- 安全框作为项目合同记录并以当前抖音 UI 复核，不声称为永久官方值。
- 产品截图完整 `contain`；AI 图不伪造产品界面。
- 没有 IP 参考图时暂停生成月明宇航员，不用通用宇航员替代。
- 转场不使用全屏绿色、白色刷新或贯穿正文的扫描线；点击声独立音轨并压在人声下。
- 用户确认预览后才渲染整片 4K/60fps；确认后的修改会重新触发预览门。

## 回归提示

用同一请求分别测试：正常制作、要求跳过预览的赶工、缺少 IP 参考图、只改语音倍速、产品截图横竖比例混合。验证输出决策，而不是只检查 Skill 文本是否包含关键词。
