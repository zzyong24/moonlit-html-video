# 制作工作流

## 输入合同

| 输入 | 必需 | 用途 |
|---|---:|---|
| 口播 MP3/WAV | 是 | 唯一主时钟 |
| SRT | 是 | 字幕与语义时间边界 |
| 已确认脚本 | 是 | 论证、分镜和重点词依据 |
| 产品截图/录屏 | 产品内容必需 | 机制与结果证据 |
| 月明宇航员参考图 | 使用 AI IP 图时必需 | 锁定角色身份 |

缺少产品证据时，不用 AI 图伪造产品界面。缺少 IP 参考图时，不生成“近似宇航员”。

## 导演顺序

1. 写一句 motion thesis：让哪个视觉主语从什么状态变成什么状态，以证明什么观点。
2. 按 SRT 语义拆 beat，不按固定秒数硬切。每拍记录 start/end、narrative job、main object、state change、asset need、transition、risk。
3. 先连续覆盖整条口播，再设计局部动效；不能用“场景稍后有素材”掩盖当前空窗。
4. 视觉优先级：真实产品证据 → 语义匹配 AI 场景图 → 专属 HTML 动效 → 当前原句基础信息动效。
5. 一个 beat 只保留一个主视觉。三个以上同权圆角卡、编号和直线箭头属于动态 PPT，重做。

## 生产顺序

1. 将原始媒体放入 `assets/source/`，产品素材放入 `assets/product/`，IP 参考图放入 `assets/reference/`。
2. 用原始 1.0 倍时间填写场景和章节；不要手工写倍速后的时间。
   更换旁白时先按 [voiceover.md](voiceover.md) 获取新音频与字幕，依据语义重新排时。供应商段落时间戳和字数估算的句内边界必须区分记录；估算边界需听查校准。
3. AI 场景图生成后复制到 `assets/ai-broll/`，在 `scenes.json` 以相对路径引用。
4. `build_composition.py` 负责生成倍速音频、字幕、HTML 时间轴、顶部进度和 SFX 音轨。
5. `validate_project.py` 先检查时间覆盖、素材存在、倍速和安全框；再运行 HyperFrames check。
6. 预览至少抽取：开场、每个转场前/中/后、每个产品截图、每个 AI 图、每个章节切换、结尾。

## 预览门

不接受“赶时间所以跳过用户预览”。可以降低预览分辨率，不能跳过真实注册时间线。用户确认后任何 composition、素材、字幕、SFX 或时间变更都使原确认失效，必须重新预览。
